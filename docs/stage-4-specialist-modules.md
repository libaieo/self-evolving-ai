# 단계 4 — 전문 모듈 실행 체계

## 목적
요청 종류에 따라 등록된 전문 모듈을 선택하고, 공통 결과 형식으로 실행 결과를 반환합니다.

## 추가된 구성
- `modules.py`: `SpecialistModule` 인터페이스 계약과 `ModuleResult` 공통 출력 형식
- `specialist_modules.py`: 예시 모듈 2개(요약, 체크리스트)
- `registry.py`: 모듈 등록, 중복 등록 차단, 이름/별칭 기반 선택
- `dispatcher.py`: 선택한 모듈 실행 및 실패 결과 표준화
- `tests/test_modules.py`: 정상 실행, 별칭 선택, 중복 등록, 미등록 작업, 예외 처리 테스트

## 사용 예시
```python
from self_evolving_ai.dispatcher import dispatch

result = dispatch("summary", "요약할 텍스트")
print(result.to_dict())

result = dispatch("계획", "책상 정리")
print(result.to_dict())
```

## 설계상 경계
- 모듈 선택은 명시된 작업명 또는 별칭에 따른 결정론적 규칙입니다. 자연어 전체를 이해하는 AI 라우터가 아닙니다.
- 예시 모듈은 텍스트를 처리할 뿐, 인터넷 검색·파일 변경·셸 명령·외부 시스템 변경을 수행하지 않습니다.
- 모듈 오류는 `status="error"`와 진단 정보로 반환합니다. 오류 상세정보는 민감정보를 포함할 수 있으므로 실제 서비스 로그에 그대로 노출하지 않도록 해야 합니다.
- 이 단계는 모듈 구조의 시연입니다. 테스트를 실행해 통과 여부를 확인하기 전까지 단계 완료로 표시하지 않습니다.

## 완료 조건
- 최소 두 모듈을 같은 인터페이스로 등록하고 실행할 수 있음
- 등록되지 않은 작업을 오류 결과로 처리함
- 모듈 예외를 표준 오류 결과로 변환함
- 자동 테스트 결과 확인
