# 설계 결정 기록

이 문서는 자가혁신 시스템의 주요 설계 결정을 날짜순으로 기록한다. 결정이 바뀌면 기존 기록을 지우지 않고 새 항목을 추가한다.

## DEC-001 — 모듈형 구조 채택
- **상태:** 채택
- **결정:** 요청 해석, 실행, 검증, 기억, 환류, 감사 기능을 논리적으로 분리한다.
- **이유:** 기능별 시험과 교체를 쉽게 하고 오류의 영향을 좁히기 위해서다.
- **재검토 조건:** 모듈 분리로 복잡도나 성능 비용이 지나치게 커지는 경우.

## DEC-002 — 단계 번호 고정
- **상태:** 채택
- **결정:** 개발 단계의 번호와 의미를 `docs/development-roadmap.md`에서 관리한다.
- **이유:** 대화가 달라져도 단계 정의가 바뀌지 않게 하기 위해서다.
- **재검토 조건:** 단계 재구성이 필요할 때. 이 경우 로드맵과 이 기록을 함께 갱신한다.

## DEC-003 — 검증과 자기교정 분리
- **상태:** 채택
- **결정:** 검증기는 오류를 판정하고, 자기교정 관리자는 수정안을 만들고 재검증을 요청한다.
- **이유:** 결과를 만든 모듈이 스스로 통과 판정을 내리는 위험을 줄이기 위해서다.
- **재검토 조건:** 실제 테스트에서 분리가 불필요하거나 충분하지 않다고 확인되는 경우.

## DEC-004 — 지식 환류는 통제된 개선 제안으로 시작
- **상태:** 채택
- **결정:** 과거 결과에서 추출한 개선점은 먼저 제안·평가하고, 핵심 규칙을 자동 변경하지 않는다.
- **이유:** 오류가 반복 학습되거나 시스템 동작이 예기치 않게 바뀌는 것을 막기 위해서다.
- **재검토 조건:** 충분한 평가 체계와 안전한 롤백이 구현된 경우.

## DEC-005 — 비밀정보 분리
- **상태:** 채택
- **결정:** API 키, 토큰, 비밀번호를 소스 코드와 저장소 기록에 넣지 않는다.
- **이유:** 저장소 유출이나 로그 노출에 따른 계정·서비스 위험을 줄이기 위해서다.
- **재검토 조건:** 없음. 비밀정보 관리 방식은 바뀔 수 있지만 원칙은 유지한다.

## DEC-006 — 최소 실행 기반은 Python 표준 라이브러리로 시작
- **상태:** 채택
- **결정:** 초기 테스트는 Python `unittest`를 사용하고, 핵심 프로그램에는 외부 런타임 의존성을 추가하지 않는다.
- **이유:** 초보자도 설치와 실행을 단순하게 시작하고, 외부 서비스 없이 기본 실행을 검증할 수 있도록 하기 위해서다.
- **재검토 조건:** 실제 AI 모델 연결이나 모듈 실행 기능에 외부 패키지가 필요해질 때.
